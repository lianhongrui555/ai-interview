# 技术方案

> 本文档记录项目的**实现思路**，而非代码细节。
> 题目原文："我们更关注在整个项目中你的实现思路，而不是代码实现的细枝末节。"

## 一、整体架构

```
┌──────────────────────────────────────────────┐
│              用户输入（命令行）                │
└───────────────────┬──────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐
│   main.py —— CLI 交互层                       │
│   负责：菜单/循环、读取输入、打印结果          │
└───────────────────┬──────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐
│   agent.py —— 智能体逻辑层                    │
│   负责：系统提示词、对话历史组装、工具调用      │
└────────┬─────────────────────┬───────────────┘
         ↓                     ↓
┌──────────────────┐  ┌──────────────────────┐
│ llm_client.py    │  │ storage.py           │
│ 调用模型 API      │  │ JSON 读写对话历史     │
└────────┬─────────┘  └──────────────────────┘
         ↓ HTTP
┌──────────────────────────────────────────────┐
│   Ollama 本地服务  http://127.0.0.1:11434     │
│   ↓                                          │
│   本地大模型（qwen2.5:7b）                    │
└──────────────────────────────────────────────┘
```

**分层的理由**：把"和模型通信"与"业务逻辑"分开。
这样更换模型（比如换成 14B、或换成另一个模型）时，**只需要改 `llm_client.py`**，
上层逻辑完全不动 —— 这正是题目"作为 model provider"的含义。

## 二、关键技术决策

### 决策 1：为什么用 Ollama 而不是自己写推理

题目允许 `Llama.cpp` / `ollama` / `LMstudio` 任选。
选 Ollama 的理由：

- 自带模型管理与 GPU 加速（自动识别 CUDA、自动排除核显）
- 提供稳定的本地 HTTP API，天然满足"通过 API 接入应用"的要求
- 题目任务二特别强调"注意参考开源库，而不是自研一坨大的"，
  这个原则同样适用于任务一

### 决策 2：为什么用 HTTP API 而不是直接调 Python 库

- 走 HTTP 意味着**应用与模型解耦**，模型可以被替换成任何兼容服务
- 这也是真实工程中的常见做法（比如换成 OpenAI 兼容接口只需改 URL）

### 决策 3：为什么用 JSON 文件存对话历史而不是数据库

- 项目规模小，JSON 足够
- 零依赖，方便他人复现
- **明确知道局限**：数据量大或并发写入时会成为瓶颈，
  届时需要换成 SQLite 或真正的关系型数据库

### 决策 4：模型选型

依据硬件（12 GB 显存）反推：

| 候选 | 显存需求 | 决策 |
|---|---|---|
| qwen2.5:7b (Q4) | 约 4.5 GB | ✅ 采用，中文能力强 |
| qwen2.5:14b (Q4) | 约 9 GB | 备选，用于对比 |
| 32B 级 | 超过 12 GB | ❌ 需卸载到内存，速度不可接受 |

## 三、预期难点与应对

| 难点 | 应对思路 |
|---|---|
| 服务未启动 / 端口不通 | 捕获连接异常，给出"请先运行 ollama serve"的明确提示 |
| 模型首次加载慢（约 48 秒） | 界面上提示"模型加载中"，避免用户以为卡死 |
| 对话历史无限增长超出上下文 | 限制最大轮数，超出后从最早的消息开始丢弃 |
| 中文编码问题 | 显式指定 `encoding="utf-8"`，JSON 写入用 `ensure_ascii=False` |
| 用户输入非预期内容 | 所有输入加异常捕获，程序不崩溃 |
