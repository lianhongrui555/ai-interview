### ⚠️ 卡住的地方

#### 卡点 1：winget 安装 Ollama 失败，退出码 4294967295

**问题现象**

执行 `winget install Ollama.Ollama --silent`，下载与哈希校验都成功，
但 "Starting package install..." 之后长时间无响应，最终报：

```
Installer failed with exit code: 4294967295
```

**排查过程**

1. 查进程，发现 `OllamaSetup.exe` 与 `OllamaSetup.tmp` 已运行 **14.8 分钟**
2. 检查其主窗口标题为空 → 不是等待用户点击，而是**静默卡住**
3. 检查安装目录，发现 `ollama.exe`、`ollama app.exe` **已经完整落盘**
4. 直接执行 `ollama.exe --version`，能正常输出 `0.34.4`

**根因**

Ollama 的 Windows 安装包由 **Inno Setup** 打包。
`winget` 的 `--silent` 对 Inno Setup 不生效（Inno 使用 `/VERYSILENT` 等自有参数），
安装器以非预期参数启动后卡在收尾阶段。
但**文件复制阶段已完成**，缺的只是收尾：注册表登记、PATH、开机自启。

**解决方式**

结束卡住的安装器进程，手动补齐收尾步骤：

1. 结束 `OllamaSetup` / `OllamaSetup.tmp`
2. 将 Ollama 目录加入用户 PATH
3. 手动启动 `ollama app.exe` 拉起后台服务

**花费时间**：约 25 分钟

**经验**：winget 装失败时，**先去目标目录看文件是否已经装进去了**，可能只差收尾步骤。

#### 卡点 2：Ollama 服务启动后不监听端口

**问题现象**

启动 `ollama app.exe` 后等待 30 秒，检查端口 11434 **仍未监听**。

**排查过程**

1. 查进程，只有 `ollama app`（托盘程序）在跑，`ollama serve`（服务本体）没起来
2. 改为在前台手动执行 `ollama.exe serve` 观察输出
3. 发现服务其实能正常启动，日志显示 `Listening on 127.0.0.1:11434`

**根因**

两个原因叠加：

1. 托盘程序初始化较慢，30 秒等待窗口不够
2. **关键**：用了 `ollama serve 2>&1 | Select-Object -First 20` 这种管道写法，
   管道读到指定行数后关闭，**把服务进程连带终止了**，端口刚监听上就消失

**解决方式**

改为独立后台进程启动，日志重定向到文件：

```powershell
$env:OLLAMA_MODELS = 'D:\ollama-models'
& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" serve *> "D:\ollama-models\serve.log"
```

**花费时间**：约 15 分钟

**经验**：启动常驻服务时**不要用会提前关闭的管道**。

#### 卡点 3：推理速度异常（9.3 tokens/秒），一度怀疑 GPU 未生效

**问题现象**

首次测速结果：

```
生成速度 : 9.3 tokens/秒
加载耗时 : 48.00 秒
```

对 RTX 5070 Ti 跑 7B 模型而言明显异常（预期 40 tokens/秒 以上），
一度怀疑退化为 CPU 推理。

**排查过程**

1. **查服务日志确认 GPU 是否被发现**：
   ```
   inference compute id=0 library=CUDA compute=12.0
   name=CUDA0 description="NVIDIA GeForce RTX 5070 Ti Laptop GPU"
   libdirs=ollama,cuda_v13 driver=13.1 type=discrete
   total="11.9 GiB" available="10.8 GiB"
   ```
   → GPU 被正确识别为 CUDA 设备

2. **确认核显被正确排除**：
   ```
   dropping integrated GPU; to enable, set OLLAMA_IGPU_ENABLE=1
   name="AMD Radeon(TM) 610M"
   ```
   → AMD 核显被自动排除，符合预期

3. **确认模型分层情况**：
   ```
   load_tensors: offloaded 29/29 layers to GPU
   load_tensors: CUDA0 model buffer size = 4168.09 MiB
   llama_kv_cache: CUDA0 KV buffer size = 224.00 MiB
   ```
   → **全部 29 层都在 GPU，没有溢出到 CPU**

4. **用 `nvidia-smi` 确认显存实际占用**：`7146 MiB used`
   → 显存确实被模型占用，GPU 在工作

5. **重做一次"热态"测速**（模型已在显存，换短 prompt）：
   ```
   模型加载    : 0.00 秒
   生成 token  : 100
   生成速度    : 81.7 tokens/秒
   ```

**根因**

**GPU 从头到尾都正常，是测试方法有问题：**

1. **冷启动开销被平均进速度**：首次调用需把模型从硬盘加载到显存，耗时 48 秒
2. **prompt 编码损坏**：首次用的中文 prompt 在 PowerShell 传递中变成一串问号，
   导致预填充行为异常

去掉干扰后真实速度 **81.7 tokens/秒**，符合该显卡预期。

**花费时间**：约 20 分钟

**经验（重要）**

- 测性能必须区分**冷启动**与**热态**，首次调用含模型加载，不能作为推理速度参考
- 排查 GPU 是否生效的正确顺序：
  ① 服务日志 `inference compute` → ② `load_tensors: offloaded X/Y layers`
  → ③ `nvidia-smi` 看显存 → ④ 热态重测
- **不要凭一次异常数据下结论**，要找可验证的证据
